# 技術構成（QUIZ KNIGHTS）

「ゲームの計算は進行役のブラウザ、早押しの判定と中継はサーバー」という分担のシステムです。

## 全体像

| 層 | 技術 | 役割 |
|---|---|---|
| フロント | Svelte 5（runes）+ Vite の単一ページ | 部屋一覧・進行役・参加者・紹介の4画面 |
| ゲームルール | 純粋な JS（`app/src/lib/engine/`） | 戦闘の計算。画面にもサーバーにも依存しない |
| サーバー | Cloudflare Workers + Durable Objects | 部屋ごとの状態、早押しの判定、メッセージの中継 |
| 配信 | Workers Assets | ビルドした画面を、同じ Worker から配信 |
| 通信 | WebSocket（Hibernation） | 参加者・進行役とサーバーの常時接続 |
| 公開 | GitHub Actions → wrangler deploy | `main` への push でテストし、通ればデプロイ |

## 処理の流れ

### 進行役のブラウザが、ゲームの正本

- 戦闘エンジン（`createBattle`）が、進行役のブラウザの中で動きます。
- 正解・誤答の判定、CPU の行動、ダメージ処理は、すべてここで計算します。
- 状態は JSON のスナップショットで持ち、取り消し・やり直し（最大40手）も、スナップショットで実現しています。
- CPU は、すべての「行動 × 対象」を複製した盤面で試して、いちばん効く手を選びます（`engine/ai.js`・`battle.js`）。

### サーバーは、早押しの判定と中継

- 部屋ごとに Durable Object が1つ（1〜16番）あり、部屋一覧用の Lobby が別に1つあります。
- 進行役 → サーバー: `open`（早押しの受付）、`state`（公開状態）、`priv`（本人と仲間だけに見せる持ち物）、`ask`（行動の選択を回答者の端末へ）、`save`（戦闘の全状態を預ける）
- 参加者 → サーバー: `buzz`（押した時刻）、`answer`、`profile`、`chat`

### 早押しの判定（`server/buzz.js`）

- 参加者の端末は、サーバーとの時計のずれを、16回の ping の中央値で補正します（`app/src/lib/net.js`）。
- サーバーは、押した時刻に、各人のディレイ（0〜3000ms）を足して、順位を決めます。
- 通信の遅れに応じて、待つ時間（許容）が自動で変わります。

### 進行役が落ちたときの引き継ぎ

- サーバーが、戦闘の全状態（`save`）を、Durable Object のストレージに預かっています。
- 進行役の接続が切れて15秒たつと、参加者の誰かが「進行役になる」を押せます。
- 引き継いだ人の画面が、預かっていた状態を読み込んで、続きから進めます。
- 進行役が落ちた瞬間に処理中だった操作は、その直前の状態からやり直しになります。

## 情報の見せ方

| 情報 | 誰に届くか |
|---|---|
| 公開状態（体力・状態・個数の印） | 全員 |
| 自分と仲間の持ち物の名前 | 本人と、同じ陣営の仲間だけ |
| 全員の持ち物の名前 | 進行役（進行役の端末が、全状態を持っているため） |
| 行動の選択（`ask`） | 回答者の端末だけ（本人が切断したら、進行役の画面） |

## ディレクトリ

```
app/        フロント（Svelte 5 + Vite）
  src/lib/engine/   ゲームのルール（data / context / jobs / items / ai / battle）
  src/lib/stores/   画面の状態クラス（host / play / ui / sound）
  src/lib/          通信・名簿・配信・裁定など
  src/components/   共通の部品
  src/pages/        部屋一覧・進行役・参加者・紹介
server/     Workers + Durable Objects（worker / room / buzz / lobby / config）
test/       engine / server / client / 静的検査
docs/       紹介文・スクリーンショット・この文書
```

## テスト（約4.2万件）

| 種類 | 中身 |
|---|---|
| ルールの網羅 | 全職業 × 全行動 × 全対象、組み合わせ、ランダム戦闘 |
| 固定テスト | 決まった乱数の戦闘結果を保存し、変化を検知（`npm run test:update-golden` で更新） |
| 裏技・アイテム・裁定 | 強すぎる動きの防止、ルール画面の文章とコードの照合 |
| サーバー | wrangler dev を起動して、部屋・早押し・引き継ぎを実通信で確認 |
| 画面の状態 | 参加者・進行役の状態クラスを、偽のサーバーで確認（Vite でルーン付きの `.svelte.js` を読み込む） |
| 静的検査 | 全 Svelte のコンパイル、import、孤立ファイル、未使用 import |

## 公開

- `main` へ push → GitHub Actions が、テストとビルドを行い、通れば `wrangler deploy`。
- 必要な鍵: GitHub の Secrets に `CLOUDFLARE_API_TOKEN` と `CLOUDFLARE_ACCOUNT_ID`。鍵がないときは、デプロイだけをスキップします。
- 手元からは `npm run deploy`（ビルドしてデプロイ）。

## 弱点・注意点

- **進行役の端末を信頼する作りです。** 計算を進行役の端末が行うので、進行役が改ざんすれば、ゲームの内容は変えられます。身内での利用が前提です。
- **認証がありません。** 参加者の識別は、ブラウザに保存した ID と、部屋のパスワードだけです。 荒らし・負荷・不正な入力への備え（回数・大きさの上限、総当たり対策、入力の掃除、CSP など）は、[SECURITY.md](SECURITY.md) にまとめています。
- **デプロイ直後の部屋は、古いままのことがあります。** 動いている部屋のサーバーは、閉じて作り直すまで、新しい仕組みに替わらないことがあります。
- **Cloudflare の無料枠で動いています。** 規模が大きくなると、Durable Objects の利用量に注意が必要です。
