# 問題読み込み・問読み・CPU早押しの設計

2つの役割に分けます。問題集の JSON は、Claude のチャットで作り、アプリは、それを取り込んで使います。

```
┌──────────────────────────┐   問題集.json   ┌─────────────────────────┐
│ ① 問題集 JSON の作成       │ ─────────────▶ │ ② クイズアプリ（QUIZ KNIGHTS）│
│ （Claude のチャット）      │                 │  取り込み・表示・早押し・CPU │
└──────────────────────────┘                 └─────────────────────────┘
```

- ①の依頼文は [QUESTION_PROMPT.md](QUESTION_PROMPT.md)。区切りや確定ポイントを、問題文の中に印として書かせます。
- ②は、JSON を受け取って使うだけです。作る側の AI が変わっても、②は変わりません。
- 受け渡しは**ファイル（JSON）だけ**。サーバーも鍵も要りません。

## 1. 問題集 JSON の形式

```json
{
  "version": 1,
  "title": "サンプル問題集",
  "questions": [
    {
      "no": 1,
      "q": "日本で/一番高い/山は/何でしょう？",
      "a": "富士山",
      "alt": ["ふじさん", "富士"],
      "wrong": ["北岳", "穂高岳", "立山"]
    }
  ]
}
```

`q` の中の印を、アプリが読み取ります。`cuts`（区切りの位置の配列）と `sure`（確定ポイントの文字数）を、直接書く形も使えます。

| 項目 | 必須 | 意味 |
|---|---|---|
| `no` | ○ | 問題番号（重複不可。無ければ順に補う） |
| `q` | ○ | 問題文。`/` は区切り、`｜` は確定ポイントの印（1問に1つ） |
| `a` | ○ | 正解 |
| `alt` | | 正解として認める別表記 |
| `wrong` | | 誤答の候補（CPU が誤答したときの答え） |
| `genre` | | ジャンル（短い言葉） |
| `diff` | | 難易度 1〜5（今のところ、CPUの動きには使っていない） |
| `guess` | | 先走りの位置（塊の番号、1から）。確定ポイントより前 |
| `traps` | | 引っかけ `[{ "chunk": 塊の番号, "a": 誤答 }]`（最大4つ）。CPUが引っかかったときの答え |
| `cuts` | | 区切りの位置（文字数の昇順の配列）。`q` の `/` と合わせて使える |
| `sure` | | 確定ポイント。そこまで読めば答えが一意に絞れる位置（文字数）。`q` の `｜` が優先 |
| `reading` | | 読み上げ用の読み仮名（将来用。今は未使用） |

取り込み時の検査: 空の `q`/`a`、重複した `no`、範囲外の `cuts`・`sure` は警告して除く（直せない問題は取り込まない）。1行1問（`問題文 || 正解 || 確定ポイント`）でも取り込める。

## 2. クイズアプリ（②）

### 2-1. 取り込みと保存
- 進行役の準備画面（バトル中はメニュー）の「📚 問題集」から、JSON を選ぶ・貼り付ける。
- 保存先は、進行役のブラウザ（localStorage）。**問題文はサーバーにも参加者にも送らない**。
- 一覧と、1問ごとの編集（スラッシュ・確定ポイントの移動、別表記・誤答候補の編集）ができる。

### 2-2. 管理者の画面に問題文を表示（カラオケ表示）
- 問題文が、**一定の速さ（字/秒。2〜20、既定7）で1文字ずつ**読み進み、読んだ部分の色が変わる。
- `Space` で読み始める・一時停止・再開。`→` で次の塊の終わりまで進める、`←` で前の塊の初めに戻す。速さは画面で変えられ、端末に保存される。
- 誰かが押すと、**押された位置で止まり**（✋）、「続きを読む」で再開できる。
- 参加者の画面には、問題文を出さない（文字で読めてしまい、早押しの条件が変わるため）。

### 2-3. 問読み
- 読むのは進行役（人間）。画面の進行は、読むペースの目安。速さは進行役が合わせる。
- 将来、読み上げ（Web Speech、VOICEVOX）を足せる。

### 2-4. 押した位置の判定
- サーバーが、勝者の押した時刻（ディレイを足す前の時刻、サーバー時刻）を `winner` に入れて知らせる（`at`）。
- 進行役の端末が、読み進めた区間（開始時刻・位置・速さ）を記録しておき、押した時刻から「何文字目まで読まれていたか」を計算する。一時停止・速さの変更・手動の移動があっても、正しく求まる。
- 既存の早押し判定（`server/buzz.js`）は、そのまま使う。

### 2-5. CPU の早押し
- CPU ごとに「押す位置（文字数）」と「正解するか」を、問題が始まるときに決める。
  - 結果の割合は、強さ・性格に関係なく一定: **スルー15%・誤答25%・正解60%**（`CPU_RATE`）。基準は `sure` で、強さ（弱い・普通・強い）は、確定ポイントを過ぎてから押すまでの文字数と、反応の速さに効く。
  - 確定ポイントが無い問題では、押さない。
- 読み進めて、その位置に達したら、CPU が押す。**CPU の押下は、参加者と同じようにサーバーへ送られ（`cpu_buzz`）、押した時刻で比べられる。** いちばん早い者が回答権を取る。
  - 参加者の画面にも、「回答権：魔王1」と出て、順位表（1着・2着 +〇〇ms）に CPU が並ぶ。人間とCPUが本当に早押しで競っているように見える。
  - CPU が押した時点で、問読みは止まる（人間が先に押していた場合も、押された位置で止まる）。
  - CPU が回答権を取って正解: 誰も行動できずに問題が終わる（CPU はいつも通り行動する）。
  - CPU が回答権を取って誤答: CPU が誤答の罰（2ダメージ。魔王は設定しだい）を受け、受付を出し直して、参加者がもう一度早押しする。
- **人間らしさ**:
  - 性格（せっかち・慎重・博識・ムラっ気）が、CPUの名前から決まる。押す早さ、先走り、押さない、知ったかぶり、反応の速さが変わる。
  - 押し方は4種類: わかって押す（正解）／先走り（確定ポイントの前に押す。35%は運よく当たる）／引っかけに乗る（`traps` の位置で、その答えを言って誤答）／知ったかぶり（確定ポイント以降に押すが誤答）。わからないときは押さない（スルー）。
  - 「わかった」位置に達してから、反応の遅れ（120〜600ms、強さで変わる）のあとで、実際に押す。その間に人間が押していたら、CPUは押さない。
  - 気分: 誤答の直後の2問は慎重（誤答が減り、その分スルーが増え、反応が遅くなる）。正解が続くと強気（押すのが早くなる）。
  - CPUの答え（「魔王1「北岳」誤答…」）が、全員の画面に出る。
- **CPU が行動するのは、早押しに勝った問題だけ。** 問題集があり、「CPUも早押しする」がオンのとき、参加者に押し負けた問題や、スルーした問題では、CPU は行動しない（勝って正解した CPU 自身が、1回行動する）。問題集を使わないとき・オフのときは、これまでどおり、1問ごとに CPU が1体動く。
- 回答者がすでに決まっている間は、押さない。サーバーにつながっていないときは、サーバーを通さずすぐに回答する。「CPUも早押しする」で切り替えられる。
- 割り切り: CPU は知識で答えているのではなく、位置で正誤を決めている。

## 3. 問題集 JSON の作成（①）
- Claude のチャットに、[QUESTION_PROMPT.md](QUESTION_PROMPT.md) の依頼文と、問題集（PDF・テキストなど）を渡す。
- 出力は、`q` に `/` と `｜` を書き込んだ JSON。50問ずつに分けて出してもらい、2回目以降は「末尾に追加」で取り込む。
- 確定ポイントの判断は、AI でも間違えることがある。取り込んだあと、問題集の画面で直せる。

## 5. 取り扱いの注意
- 問題集は、進行役のブラウザ（localStorage）にだけ保存される。参加者にも、サーバーにも送らない。
- 市販・配布されている問題集から作った JSON は、公開リポジトリに入れない（`scratch/` などの、Git に入らない場所に置く）。

## 6. 決定済み
- 問読みは、**一定の速さで1文字ずつ進む**（カラオケ表示）。
- 参加者の画面には**問題文を出さない**。
- 確定ポイント `sure` は**文字数**で持つ（`q` の `｜` の位置から求める）。
- 問題集 JSON は Claude のチャットで作る。アプリ側に作成ツールは持たない。
